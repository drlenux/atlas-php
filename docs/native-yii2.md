# Нативный плагин Yii2

`Yii2Plugin` реализует `FrameworkPlugin` (`id = yii2`, `language = php`). Плагин получает исходники и готовый PHP-граф, использует общий Rust-токенизатор PHP и добавляет знания фреймворка. Исходники проекта не исполняются; PHP, Composer и subprocess не требуются.

## Статическая семантика

- Свойства объектов, наследующих `yii\base\Component` или `yii\base\BaseObject`, сопоставляются с `getX` / `setX`. Поиск учитывает родительские классы, traits и `available_via`, включая объявления из vendor. Рёбра становятся `magic_get` / `magic_set`.
- Вызовы методов и свойства через behaviors рассматриваются только у потомков `yii\base\Component`. Плагин читает статический массив, возвращаемый `behaviors()`, включая унаследованный метод, строковые имена классов, `Class::class`, namespace/import aliases и конфигурацию `['class' => ...]`.
- `Yii::$app->component->method()` рассматривается только при установленном PHP-анализатором глобальном классе `Yii`. Одноимённый класс другого namespace не получает семантику Yii. Классы компонентов извлекаются из статических массивов `components`.
- Единственное известное соответствие получает `to`. Несколько конфигураций, неизвестный класс, динамическая карта компонентов, переменный ключ или runtime spread сохраняют `to = null`, доступные `metadata.candidates` и диагностическую неопределённость. Условные или вычисляемые behaviors не подтверждают реализацию; return вложенного замыкания не считается return метода.
- Обычные PHP-классы с методами `getX` или `behaviors()` остаются обычными классами. Динамические имена членов не угадываются. Уже разрешённые PHP-связи не переписываются.

Это анализ статически доступных определений, а не доказательство runtime-конфигурации приложения. Выполнение closures, bootstrap, контейнера и динамическое присоединение behaviors не моделируются. Проверки deadline и лимита графа используют общий `AnalysisOptions`; ошибка обогащения передаётся вызывающему реестру.

## TDD и проверка

`tests/native_yii2.rs` содержит 10 проверок, включая настоящий конвейер `PhpLanguagePlugin -> Yii2Plugin` на исходниках приложения, vendor и config.

1. Начальная красная фаза: тесты не компилировались, поскольку `code_atlas::plugins::yii2` ещё не существовал.
2. После реализации исходные 6 тестов прошли.
3. Регрессия динамической карты компонентов воспроизвела ложное разрешение статического mailer (`an unknown component map can override the static mailer`). После распространения признака неизвестности все 8 тестов прошли, включая реальный PHP→Yii2 конвейер.
4. Два отдельных теста воспроизвели ложное разрешение класса при runtime spread и ошибочное использование return вложенного замыкания. После исправления все 10 тестов прошли.

```sh
cargo test --offline --test native_yii2
```

На первоначальном PHP checkpoint Clippy обнаружил замечания языкового плагина; они исправлены в итоговой интеграции. Полный `cargo clippy --offline --locked --all-targets -- -D warnings` проходит. Независимое включение/выключение через реестр и ENV проверено интеграционным тестом `native_runtime` с пустым PATH.
