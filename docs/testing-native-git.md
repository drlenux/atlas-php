# Нативный Git: контракт до реализации

Runtime-адаптер читает Git напрямую и не запускает внешние процессы. Системная zlib используется только для распаковки объектов; собственный код разбирает refs, commit/tree/blob, pack index v2 и OFS/REF delta. SHA-1 проверяется для загруженных объектов. Поддерживаются обычный `.git`, gitfile и `commondir` связанных worktree.

`GitReader`, `history` и поля результата сохраняются. Новый `head(root)` нужен наблюдателю. `after` остаётся текущим кодом; `at_commit` — историческим контекстом; строка и весь участок имеют отдельные сведения об изменении.

История сопоставляет строки с ограниченным diff и проходит родителей коммитов без исполнения исходников. Неоднозначные переименования, недоступные границы истории, неподдержанные варианты формата и превышение лимитов возвращают явную недоступность. Полная имитация всех опций Git blame не заявляется.

TDD: прежние семь проверок сохраняются. До замены адаптера добавляются тесты, запускающие чтение истории в отдельном процессе с пустым PATH, включая loose/packed repositories и связанные worktree. Git разрешён только для создания fixtures родительским тестом; глобальный PATH тестового процесса не изменяется.

## Реализованные границы

- SHA-1, loose objects, pack v2/v3, index v2, OFS/REF deltas; содержимое каждого запрошенного объекта проверяется по его SHA-1. Pack/index checksum целиком не пересчитывается. Не выполняются команды, hooks, filters, textconv или код проекта.
- HEAD: символический или detached, loose/packed refs; `.git` directory/file и `commondir`. `head(root)` читает те же данные напрямую. Git CLI используется только родительскими тестами для создания fixtures.
- История проходит первого родителя. Если запрошенные строки изменились относительно первого родителя merge-коммита, результат явно недоступен: происхождение из другой ветки не угадывается. Однозначное переименование с тем же blob сохраняет историю; переименование с изменением текста и несколько подходящих удалённых файлов дают явную недоступность.
- Shallow/partial boundary, недоступный объект, SHA-256, index v1, reftable, alternates, не-UTF-8 исходники и неоднозначное сопоставление не поддерживаются. Replacements/grafts и параметры пользовательского Git config не применяются: читается исходная объектная история.
- Лимиты: текущий исходник 16 MiB; объект 32 MiB; сжатый поток 64 MiB; одна цепочка распаковки 128 MiB; глубина delta 64; pack indexes до 256, один index до 64 MiB; cache объектов до 64 MiB/4096 записей. Pack читается с нужного offset, целиком в память не загружается.
- Один поиск происхождения: до 512 коммитов и проверка бюджета 15 секунд между коммитами; tree depth 128 и до 100000 записей при поиске переименования. Diff: до 200000 строк и 4 млн ячеек LCS после удаления общего начала/конца; превышение даёт диагностику. Выдача diff ограничена 400 строками и содержит маркер усечения. Это ограниченный поиск истории, а не полная реализация всех опций `git blame`.

Формат сверялся с официальными [Git pack format](https://git-scm.com/docs/gitformat-pack) и [repository layout](https://git-scm.com/docs/gitrepository-layout). Для сборки нужен системный zlib; runtime использует только библиотеку `libz`, без исполняемого Git.
