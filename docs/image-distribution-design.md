# Поставка готового Docker-образа

Уточнение владельца: Atlas собирается один раз, публикуется в registry через docker push и подключается в чужой проект только описанием сервиса Compose. Получателю не нужны checkout Atlas, Cargo, Dockerfile или локальная сборка.

## Границы до реализации

- Dockerfile остаётся единственным рецептом образа: PostgreSQL/pgvector, Atlas со встроенными плагинами, веб-ресурсы, миграции и entrypoint. Healthcheck и стабильные пути приложения входят в образ.
- Основной docker-compose.yml использует только image из ATLAS_IMAGE. Рецепт локальной сборки вынесен в отдельный docker-compose.build.yml и не требуется получателю.
- examples/compose.atlas.yml — самостоятельный фрагмент сервиса и named volume для добавления в чужой Compose без extends/include и ссылок на файлы Atlas.
- Переменные хоста для встроенной БД имеют префикс ATLAS_POSTGRES_: чужой POSTGRES_PASSWORD/POSTGRES_DB не должны случайно настраивать Atlas. Внутри контейнера POSTGRES_* и PG* получают согласованные значения. Токены передаются ENV при запуске, не при сборке.
- Исходный проект примонтирован read-only; БД хранится в отдельном Compose-scoped named volume. Нет container_name, глобального имени volume или зависимости от сервисов приложения. У каждого проекта свой индекс.
- Публикация имеет два документированных пути: docker build + docker push для выбранной платформы и Buildx --platform linux/amd64,linux/arm64 --push для общего тега. Владелец указал Docker Hub drlenux/memory-tools; default tag 0.1.0 соответствует Cargo.toml. ATLAS_IMAGE может переопределить его. Выбор адреса не означает, что публикация выполнена.
- Обновление — смена image tag/digest, pull и up только сервиса atlas. Данные сохраняются в named volume; major PostgreSQL upgrade не считается обычным обновлением тега.

## Проверка

До изменения Compose проверяется ожидаемый отказ старого build-зависимого варианта. Затем Compose config выполняется в отдельной чужой папке, без исходников Atlas, вместе с посторонним сервисом PostgreSQL и конфликтующими POSTGRES_* переменными. Проверяются маршруты mount, независимый volume, согласованные PG credentials, образ владельца по умолчанию/переопределение и отсутствие build. Это проверка контракта установки, а не доказательство Docker build/push. Недоступный Docker daemon отмечается отдельно.

## Исправление после запуска получателем

Пользователь предоставил restart-loop с `ATLAS_PROJECT_ROOT is required` после успешного запуска PostgreSQL. Минимальный Compose зависел от defaults конкретного image; фактический image/ENV контейнера агентом не проверен. Контракт установки уточняется: consumer Compose явно передаёт ATLAS_PROJECT_ROOT=/project, ATLAS_BIND=0.0.0.0:8080 и ATLAS_DATABASE_URL для локальной БД. Образ может дублировать эти defaults, но отсутствие defaults в уже собранном образе не должно ломать пример. Config сохраняет строгую проверку обязательных параметров. Исправление применяется пересозданием сервиса с прежним volume без пересборки образа.
