# Ограниченный параллелизм индексации: проверка 2026-11-04

Контракт INDEX-06 и границы компонентов записаны до production-кода в [design.md](../openspec/changes/add-code-atlas/design.md). Один процесс Atlas теперь использует ограниченные scoped threads для независимого разбора PHP и сбора Git-истории. Последовательный режим остаётся доступен через `ATLAS_INDEX_WORKERS=1`.

## Наблюдаемая последовательность TDD

1. Тесты Config потребовали отсутствующее поле `index_workers`; тест consumer Compose получил `None` вместо `"0"`. После добавления настройки проверены default/auto по CPU, явные overrides и отклонение значений вне 0..32.
2. PHP-регрессия с ошибочными файлами между успешными, замыканием и наследованием сравнивает графы при 1 и 4 workers. До подключения worker pool проверка `workers=0` не получала ожидаемую ошибку. После подключения и детерминированного объединения проверка проходит; индексы успешных Unit и ключи closures переназначаются после пропущенных файлов.
3. Проверка Git snapshot сначала не компилировалась без нового контракта. После реализации clones используют один HEAD и общий объектный cache. Тест временно перемещает objects только собственного fixture после прогрева первого reader: второй reader читает историю из общего cache. После восстановления objects и нового commit оба старых reader сохраняют исходный HEAD, новый reader видит новый commit.
4. Node-тест счётчика потоков сначала получил `undefined` вместо ожидаемой строки. После изменения модели и панели показывает занятые/доступные workers и скрывает устаревшие данные при потере соединения.
5. Worker pool проверен независимым барьером: четыре задачи реально перекрываются, peak равен четырём, итоговые слоты сохраняют порядок. Fatal error прекращает выдачу следующих задач; panic преобразуется в ошибку после join. Пустой набор не создаёт workers.
6. Конкурентная проверка прогресса видит четыре активные задачи и ровно 100 завершений без потери инкрементов. Следующая стадия сбрасывает счётчики потоков.
7. Сквозные проверки сравнивают полный контекст PHP/Yii, Git и отчёт при одном worker с loose objects и четырёх workers после repack того же fixture. Фатальное превышение бюджета оставляет предыдущий опубликованный граф и ставит статус failed без активных workers. В первой редакции интеграционный тест ошибочно искал диагностику одного файла в контексте чужого метода; утверждение исправлено на диагностики общего отчёта, фильтрация сервиса не менялась.

## Локальный замер

Отдельный синтетический Git-репозиторий: 128 PHP-файлов, 16 методов в каждом, шесть commits с изменением возвращаемых значений, `repack -adf` и `prune-packed`. Получено 6272 nodes, 38912 edges и 0 diagnostics во всех четырёх запусках. Release-бинарник выполнен на macOS, без Docker quota; публикация в MemoryRepository. Компилятор и другие тесты во время замера не запускались.

Порядок запусков: 1, 4, 4, 1 workers. Это два наблюдения на настройку, без принудительной очистки файлового cache. Время в таблице измерено внутри `IndexCoordinator.index`, включая публикацию; RSS — peak дочернего процесса через `os.wait4` (Darwin bytes), переведённый в MiB.

| Workers | Первый замер | Повтор | Peak RSS, два запуска |
| --- | --- | --- | --- |
| 1 | 5633 мс | 5676 мс | 522–523 MiB |
| 4 | 2717 мс | 2650 мс | 514–521 MiB |

На этом fixture четырёхпоточный проход занял примерно в 2,1 раза меньше времени. Память на этом fixture не выросла; это не гарантия для других исходников или историй. Общий Git cache ограничен 64 MiB/4096 объектов и одним pack index до 64 MiB, но одновременно выполняемые decode/diff могут держать дополнительные временные буферы. Последовательные графовые проходы и сохранение ограничивают дальнейшее ускорение.

Для замера на другом корне без подключения к БД:

```sh
cargo build --locked --release --example index_profile
target/release/examples/index_profile /path/to/project 1
target/release/examples/index_profile /path/to/project 4
```

Пример только читает исходники и Git, а граф хранит в памяти отдельного процесса. Он выводит время/отчёт в stdout и прогресс в stderr; PostgreSQL и HTTP в этот замер не входят. Системная `/usr/bin/time -l` в sandbox завершилась ошибкой `sysctl kern.clockrate: Operation not permitted`, поэтому для RSS использован `wait4`.

## Границы доказательств

Настоящая БД, Linux-образ, CPU/RAM контейнера владельца и живой браузер не проверены: Docker API socket и browser access host недоступны, локальный TCP listener запрещён. Многопоточность не является подтверждённым исправлением ранее присланного `Killed`; причина SIGKILL не установлена. Настройка/пересборка описаны в [distribution.md](distribution.md#параллельная-индексация).
