# Наблюдение и переиндексация проекта

## Purpose

Поддерживать атлас при изменении файлов проекта посредством постоянного наблюдения, автоматической переиндексации и настраиваемых условий запуска анализа.

Источник: [ТЗ](../../../../../code-atlas-specification.md), разделы 7.1–7.3 и 9.1. Нерешённые детали: [Q-08, Q-13, Q-14, Q-16](../../open-questions.md).

## ADDED Requirements

### Requirement: INDEX-06 Ограниченные рабочие потоки

Индексатор SHALL выполнять независимый разбор PHP-файлов несколькими рабочими потоками с пределом ATLAS_INDEX_WORKERS. Порядок объединения результатов SHALL сохранять поведение последовательного режима; публикация SHALL происходить одной транзакцией только после завершения всех workers и проверки исходников. Количество workers SHALL NOT создавать копию всего проекта на каждый поток. Сбор Git-истории не выполняется.

#### Scenario: Настроены четыре потока

- **WHEN** ATLAS_INDEX_WORKERS=4 и этап содержит несколько независимых задач
- **THEN** одновременно работают до четырёх workers и задачи действительно могут перекрываться
- **AND** прогресс показывает общий монотонный счётчик и число занятых workers

#### Scenario: Последовательный и параллельный результат

- **WHEN** один проект, включая ошибочные файлы, индексируется с 1 и 4 workers
- **THEN** полученный граф и диагностики совпадают
- **AND** у узлов отсутствует `metadata.git`

#### Scenario: Ошибка worker

- **WHEN** worker получает fatal error или паникует
- **THEN** выдача новых задач прекращается и начатые workers завершаются до возврата ошибки
- **AND** частичный граф не публикуется и статус индексации становится failed

#### Scenario: ENV и границы числа потоков

- **WHEN** ATLAS_INDEX_WORKERS равен 0 или отсутствует
- **THEN** число workers выбирается из округлённого вверх ATLAS_CPU_LIMIT в пределах 1..32
- **AND** явное значение 1 включает последовательный режим, а отрицательное, дробное или большее 32 значение отклоняется при старте

### Requirement: INDEX-05 Наблюдаемый прогресс индексации

Система SHALL показывать в веб-интерфейсе и runtime stderr текущий этап индексации, обработанные единицы из известного общего количества и прошедшее время. Веб SHALL показывать progressbar этапа и приблизительное оставшееся время этапа только при достаточных наблюдениях. Завершение SHALL означать успешную публикацию графа.

#### Scenario: Длительная индексация

- **WHEN** индексатор читает файлы или анализирует PHP
- **THEN** разработчик видит обновляющийся счётчик текущего этапа и текущий путь
- **AND** после минимум трёх обработанных единиц и секунды измерений появляется приблизительный ETA этапа
- **AND** переход этапа сбрасывает счётчик и ETA, а неизвестный объём не изображается фиктивным процентом

#### Scenario: Публикация удерживает сервис

- **WHEN** транзакция публикации удерживает блокировку AtlasService
- **THEN** авторизованный GET /api/indexing продолжает возвращать актуальный снимок без ожидания транзакции
- **AND** запрос без reviewer token отклоняется

#### Scenario: Ошибка и повторный запуск

- **WHEN** подготовка или публикация индекса завершается ошибкой
- **THEN** состояние становится failed с причиной и временем остановки, без успешного 100% всей индексации
- **AND** следующая попытка получает новый run_id, очищает ошибку и начинает новый отсчёт

#### Scenario: Потеря связи и перезапуск

- **WHEN** браузер не может получить актуальный снимок
- **THEN** панель явно сообщает о потере связи и не выдаёт старый ETA за актуальный
- **AND** опрос автоматически возобновляется без перекрывающихся запросов
- **AND** новый процесс сервера начинает с waiting, а не с результата прошлого процесса

### Requirement: INDEX-01 Постоянное наблюдение

Система SHALL постоянно отслеживать изменения файлов в выбранных директориях проекта и направлять изменившиеся файлы на автоматическую переиндексацию. Список наблюдаемых директорий SHALL настраиваться. Ручной запуск каждого обновления не требуется.

#### Scenario: Изменение отслеживаемого файла

- **WHEN** файл в выбранной директории изменён и выполнены настроенные условия запуска анализа
- **THEN** система автоматически направляет этот файл на переиндексацию
- **AND** отдельный ручной или MCP-запрос для каждого обновления не требуется

### Requirement: INDEX-02 Область исходного кода и исключения

Система SHALL ограничивать наблюдение кодом и нужными директориями, поддерживать исключения из индексации и не индексировать служебные каталоги, включая `.git` и каталоги инструментов агента, как исходный код. Каталог `.git` исключается из индекса кода и не используется для provenance.

#### Scenario: Служебные каталоги в проекте

- **WHEN** в дереве проекта присутствуют `.git` и служебные каталоги инструментов агента
- **THEN** их содержимое не индексируется как исходный код проекта
- **AND** Atlas не читает object store Git для построения графа

#### Scenario: Настроенные исключения

- **WHEN** файл попадает под настроенное исключение из индексации
- **THEN** его содержимое не направляется на индексацию как исходный код

### Requirement: INDEX-03 Настраиваемая задержка

Система SHALL предоставлять настраиваемую задержку перед переиндексацией, чтобы не запускать её немедленно при серии правок. Около пяти секунд — ориентир, а не обязательное значение или установленный default. Точка отсчёта задержки определяется отдельно.

#### Scenario: Серия изменений файла

- **WHEN** файл изменён несколько раз подряд и настроена задержка обработки
- **THEN** переиндексация запускается с учётом этой задержки, а не немедленно на каждое событие

### Requirement: INDEX-04 Встроенная проверка разбора языка

Языковой плагин SHALL проверять разбор исходного текста внутри Atlas без запуска интерпретатора. При ошибке разбора файл SHALL получать диагностику; неуспешный или неподдержанный разбор SHALL NOT авторизовать удаление прежних данных файла. Ранее предусмотренный внешний `php -l` заменён уточнением владельца о нативной поставке.

#### Scenario: Корректный поддерживаемый синтаксис

- **WHEN** встроенный плагин успешно разбирает поддерживаемый исходный файл
- **THEN** результат допускается к публикации без запуска runtime анализируемого языка

#### Scenario: Ошибка разбора

- **WHEN** встроенный плагин обнаруживает ошибку разбора файла
- **THEN** файл получает диагностику и прежний граф этого файла сохраняется
- **AND** ошибка не трактуется как полное удаление кода
