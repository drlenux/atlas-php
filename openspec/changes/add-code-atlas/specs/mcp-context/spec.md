# MCP-доступ к контексту и исправлениям

## Purpose

Дать агенту связный участок атласа для исследования кода и возможность исправлять существующие знания с соблюдением полномочий и уровней доверия.

Источник: [ТЗ](../../../../../code-atlas-specification.md), G-01–G-06, D-05, разделы 6.2 и 9. Нерешённые детали: [Q-07, Q-09, Q-10, Q-16](../../open-questions.md).

## ADDED Requirements

### Requirement: MCP-01 Получение связного контекста

Система SHALL предоставлять MCP-доступ к данным атласа и возвращать связный участок карты вокруг запрошенной сущности, а не только изолированный объект. В зависимости от запроса контекст SHALL включать связанные вершины и рёбра, принадлежность, вызывающий код, сведения о ссылках и соответствующие возвраты с кодом. История Git в ответ SHALL NOT включаться. Формат ответа, глубина и предел размера определяются отдельно.

#### Scenario: Исследование метода через MCP

- **WHEN** агент запрашивает контекст метода
- **THEN** ответ позволяет определить исследуемый метод, его владельца, окружение и вызывающий код
- **AND** относящиеся к запросу связи и возвраты доступны в контексте
- **AND** поля Git-provenance в ответе отсутствуют

#### Scenario: Исследование от переменной через MCP

- **WHEN** агент запрашивает контекст переменной внутри метода
- **THEN** ответ позволяет связать переменную с методом, классом и относящимся к запросу окружением

### Requirement: MCP-02 Доверие в ответе

Система SHALL предоставлять уровни доверия вместе с относящимися к ним вершинами и рёбрами, чтобы агент мог различать результат анализатора, исправление агента и подтверждение разработчика. Доверие к вершине SHALL NOT заменять доверие к её связям.

#### Scenario: Разные уровни у вершины и ребра

- **WHEN** ответ содержит вершину уровня 3 и связанное с ней ребро уровня 1 или 2
- **THEN** для каждого объекта доступен его собственный уровень доверия
- **AND** связь не представляется подтверждённой разработчиком только на основании доверия к вершине

### Requirement: MCP-03 Исправление существующих данных атласа

Система SHALL позволять агенту через MCP сообщить об ошибочности существующих сведений и обновить существующую вершину или связь по правилам `knowledge-trust`. Исправление SHALL относиться к данным атласа, а не к изменению исходных файлов проекта. Создание и удаление объектов агентом не разрешены; состав допустимого обновления ребра определяется отдельно.

#### Scenario: Исправление сведений анализатора

- **WHEN** агент через MCP исправляет допустимые данные существующей вершины или связи уровня 1
- **THEN** исправление становится действующими данными уровня 2
- **AND** операция исправления атласа не изменяет исходные файлы проекта

#### Scenario: Попытка исправить подтверждённые данные

- **WHEN** агент через MCP пытается перезаписать данные уровня 3
- **THEN** подтверждённые данные не перезаписываются этим запросом

#### Scenario: Попытка создать или удалить объект

- **WHEN** агент через MCP пытается создать или удалить вершину либо ребро
- **THEN** такая операция не разрешается
