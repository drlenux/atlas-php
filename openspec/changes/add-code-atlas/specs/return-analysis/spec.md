# Возвраты функций и методов

## Purpose

Сохранять отдельные случаи возврата, включая неоднородные типы legacy-кода, и предоставлять агенту условия, исходный код и происхождение возвращаемых значений.

Источник: [ТЗ](../../../../../code-atlas-specification.md), раздел 5, R-01–R-06. Нерешённые детали: [Q-09, Q-11](../../open-questions.md).

## ADDED Requirements

### Requirement: RETURN-01 Все явные возвраты

Вершина функции или метода SHALL содержать сведения обо всех принадлежащих ей явных `return`: расположение со строкой возврата, возвращаемое выражение или значение и тип для каждого отдельного случая. Система SHALL NOT сводить разные возвраты к одному случаю или общему типу с потерей отдельных вариантов. Представление неизвестного типа определяется отдельно.

#### Scenario: Возвраты разных типов

- **WHEN** метод в разных ветвях возвращает `null`, целое число, строку, объект или ресурс
- **THEN** каждый `return` представлен отдельно со своей строкой, выражением или значением и типом
- **AND** отдельные случаи сохраняются даже при наличии общего описания типа метода

#### Scenario: Несколько возвратов одного типа

- **WHEN** функция содержит несколько `return` со строковыми значениями в разных местах
- **THEN** доступны все эти возвраты со своими расположениями и выражениями без слияния по совпадению типа

### Requirement: RETURN-02 Условия каждого возврата

Система SHALL предоставлять условия, при которых происходит каждый возврат, включая относящиеся к нему ветвления `if`. Формат условий и представление неустановленного условия определяются отдельно.

#### Scenario: Возврат внутри вложенных условий

- **WHEN** `return` находится внутри вложенных ветвей `if`
- **THEN** сведения об этом возврате включают относящиеся к нему условия этих ветвлений

### Requirement: RETURN-03 Код и происхождение значения

Система SHALL хранить небольшой фрагмент исходного кода вокруг каждого `return`, ориентировочно две-три строки выше и ниже, и позволять увидеть происхождение возвращаемого значения без обязательного дополнительного текстового поиска. Способ расширения контекста за пределами фрагмента определяется отдельно.

#### Scenario: Локальный фрагмент возврата

- **WHEN** агент получает сведения о конкретном `return`
- **THEN** доступны строка возврата и небольшой фрагмент окружающего исходного кода

#### Scenario: Источник значения вне фрагмента

- **WHEN** возвращаемое значение получено значительно выше `return` или из другого метода
- **THEN** доступные сведения позволяют увидеть происхождение значения за пределами локального фрагмента без обязательного дополнительного текстового поиска
