# Design: incremental-indexing

## Architecture

```
observer thread: discover() каждые ATLAS_POLL_MS ─► latest scan
                 ─► progress.set_pending(paths ≠ published)
watcher thread:  debounce(latest scan) │ reindex request
                 ─► coordinator.prepare(Mode::Full | Mode::Incremental)
                 ─► publish(scope) ─► published = scan, surface = new
```

### Поверхность объявлений

`analyzer::incremental::declaration_surface(nodes) -> BTreeMap<path, BTreeSet<entry>>`. Источник — вершины kind `class|interface|trait|enum|method|function|property|constant` без замыканий. Запись — `id` плюс значимые для типов поля metadata: `type`, `type_source`, `declared_return_type`, `annotated_return_type`, `parameters`, `parent`, `interfaces`, `traits`, `magic`, `access`, `relation`, `implemented_by`. Строки, fingerprint и тела не участвуют, поэтому правка тела или сдвиг строк поверхность не меняют. Члены фреймворка (связи, компоненты) тоже вершины `property`. Поэтому смена класса компонента в конфиге — изменение поверхности конфига.

### Область анализа

`incremental_scope(changed, removed, previous, current, files, hierarchy) -> Option<BTreeSet<path>>` — чистая функция, общая для PHP-плагина (до анализа тел) и координатора (для фильтрации и публикации), поэтому оба получают одну и ту же область.

1. Изменённые записи — симметрическая разность поверхностей изменённых и удалённых путей.
2. Имена членов из изменённых записей (`method:A\B::m` → `m`, `property:…::$p` → `p`, `constant:…::C` → `C`). Имена классов — только если добавлен, удалён или изменён сам класс (родитель, интерфейсы, трейты).
3. Область = изменённые пути ∪ файлы, в тексте которых имя встречается как идентификатор ∪ файлы конкретных наследников (по `parent`/`interfaces` текущих вершин) классов, у которых изменились члены.
4. Если область больше `max(50, 25 % файлов)`, результат `None`: нужна полная пересборка.

### PHP-плагин и координатор

`AnalysisOptions.incremental: Option<Incremental { changed, removed, previous_surface }>`. PHP-плагин после объявлений и членов фреймворка вычисляет текущую поверхность и область. Тела анализируются только у функций из области. Если `None` — у всех.

Координатор хранит в памяти `published` (хэши файлов последней публикации) и `surface`. Инкрементальная подготовка: `changed`/`removed` по хэшам, анализ с `incremental`, повторный расчёт области по возвращённым вершинам, фильтрация снимка (вершины, рёбра, диагностики) по области, публикация с `indexed_paths` = область без файлов с ошибкой разбора. Вершины объявлений вне области не публикуются: они не изменились. Если `published` или `surface` пусты или область `None`, выполняется полная пересборка.

Зависимые рёбра в БД: ребро из файла вне области на удалённую вершину удаляется каскадом (FK). Такой файл попадает в область, если упоминает имя удалённого объявления; наследники — по иерархии.

#Публикация части путей: концы рёбер, которых нет среди узлов этих путей и снимка, проверяются одним запросом `Repository::existing_node_ids` (в PostgreSQL — `id IN (jsonb_array_elements_text($1))`). Так рёбра из изменённого файла в неизменённые файлы принимаются, а действительно неизвестный конец по-прежнему отвергает публикацию с указанием id.

Переименование сохраняет идентичность узла (прежнее поведение публикации, нужное для сохранения исправлений). Меняются имя и `qualified_name`, а id остаётся прежним.

## Наблюдатель и свежесть

Отдельный поток наблюдателя сканирует файлы и хранит последнее сканирование. Watcher берёт его для debounce, а не сканирует сам. `IndexingProgress.pending_paths` — пути, хэш которых отличается от `published`, включая удалённые; до 100 путей. `changes_pending = !pending_paths.is_empty()`. `Freshness.pending_paths` отдаётся в `index`.

## Patterns

- Pure function (`incremental_scope`) вместо протокола «плагин сообщает область»: контракт `GraphSnapshot` не меняется.
- Producer/consumer (наблюдатель → watcher) через общее последнее сканирование.

## ENV

Новых переменных нет. Порог полной пересборки фиксирован (YAGNI): `max(50, 25 %)`.

## Risks / Trade-offs

- Поиск по тексту завышает область для частых имён (`save`, `get`): чаще будет полная пересборка, но не ошибочный результат.
- Тело `behaviors()` (Yii2) вне поверхности — см. proposal.
