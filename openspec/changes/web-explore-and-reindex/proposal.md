# Proposal

## Why

После `finer-graph-nodes` и `lean-mcp-responses` веб-интерфейс проверяющего на `slotor777` стал практически непригоден:

- места вызова, чтения, записи и ветки отображаются по техническому id (`call_site:method:…:php-struct-v1:<hash>:1`), а не по выражению: и в результатах поиска, и в таблице аналитики;
- контекст сущности выводится как сырой JSON (885 тыс. символов для `processingGameTransaction`), и первой идёт диагностика;
- в поиске нет фильтра по kind и пагинации: показываются первые 50 совпадений, а дальше ничего;
- браузер получает 404 на `/favicon.ico`.

Кроме того, переиндексацию сейчас запускает только изменение файлов. Владелец просит кнопку, чтобы запускать её вручную, например после обновления анализатора.

## What Changes

- Веб-поиск: фильтр по группе kind, постраничная подгрузка по `next_cursor`, компактные вершины; occurrence и branch показываются по выражению и методу-владельцу.
- Веб-контекст: структурированный вид с группами «Вызывающие», «Владелец», «Эффекты» (calls/writes/reads/returns) и «Ветки», с условиями пути и переходом к связанной сущности; полный JSON доступен по запросу.
- `/api/search` принимает `kinds` и `cursor` и возвращает `next_cursor`. `/api/context/{id}` принимает `depth`, `max_nodes`, `direction`, `detail` и `include_diagnostics`; значения по умолчанию прежние.
- Таблица аналитики подписывает occurrence и branch выражением и методом-владельцем.
- Новый `POST /api/reindex` (токен проверяющего) ставит в очередь полную переиндексацию; `/api/indexing` сообщает `reindex_queued`. В карточке индексации появляется кнопка «Переиндексировать».
- Иконка страницы, без 404.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `project-indexing`: ручной запрос переиндексации.
- `atlas-runtime`: исследование кода в веб-интерфейсе.

## Impact

- `src/progress.rs`, `src/http.rs`, `src/main.rs` (watcher), `web/*`.
- `tests/http.rs`, `tests/indexing.rs` или новый тест, `web/model.test.mjs`, `web/indexing.test.mjs`.
- Для `/api/search` меняется форма ответа (`next_cursor`, компактные вершины). Этот путь использует только поставляемый веб-интерфейс.
