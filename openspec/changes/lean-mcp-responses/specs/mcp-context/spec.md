# MCP context — компактные ответы

## ADDED Requirements

### Requirement: MCP-05 Фильтр и пагинация поиска

Поиск через MCP SHALL принимать необязательный список kind вершин и возвращать только вершины этих kind. Поиск SHALL отдавать результаты страницами и вместе с каждой страницей возвращать курсор следующей страницы. Если совпадений больше нет, курсор SHALL быть пустым. Последовательный обход страниц SHALL вернуть каждое совпадение ровно один раз.

#### Scenario: Все записи поля по голому имени

- **WHEN** агент ищет `dep_tax_control` с kinds `write_site`, а мест чтения больше, чем размер страницы
- **THEN** выдача содержит только `write_site`
- **AND** обход по `next_cursor` возвращает все места записи без повторов
- **AND** на последней странице `next_cursor` пуст

#### Scenario: Недопустимый kind

- **WHEN** агент передаёт kind с символами вне `[a-z0-9_]`
- **THEN** запрос отклоняется как недопустимый

### Requirement: MCP-06 Компактная проекция вершин

Поиск через MCP SHALL возвращать вершины без тяжёлых полей metadata (`fingerprint`, `returns`, `imports`, `assignments`, `usages`, `body`, `source`) и SHALL сохранять идентификатор, kind, имя, span, доверие, ревизию и остальную metadata. Контекст через MCP SHALL по умолчанию возвращать ту же проекцию и SHALL возвращать полную metadata по явному запросу.

#### Scenario: Поиск захватывает метод

- **WHEN** поиск находит method с возвратами и импортами
- **THEN** вершина в ответе не содержит `returns` и `imports`
- **AND** содержит `revision` и `trust`, достаточные для `atlas_correct`

#### Scenario: Полный контекст по запросу

- **WHEN** агент запрашивает контекст с `detail: full`
- **THEN** вершины содержат полную metadata, включая `returns`

### Requirement: MCP-07 Направление и бюджет контекста

Контекст через MCP SHALL принимать направление обхода `both`, `in` или `out`. Branch- и occurrence-вершины SHALL NOT расходовать предел `max_nodes`; для них SHALL действовать отдельный предел того же размера. Входящие рёбра вершины SHALL обходиться раньше исходящих. Диагностика SHALL включаться в ответ только по явному запросу.

#### Scenario: Вызывающие метода

- **WHEN** агент запрашивает контекст метода с `direction: in` и depth 1
- **THEN** ответ содержит call_site вызывающих и их методы
- **AND** не содержит собственных occurrence-вершин метода

#### Scenario: Эффекты метода

- **WHEN** агент запрашивает контекст метода с `direction: out` и depth 1
- **THEN** ответ содержит собственные occurrence-вершины метода и цели их эффектов
- **AND** не содержит вызывающих

#### Scenario: Места чтения не вытесняют вызывающих

- **WHEN** метод содержит больше `read_site`, чем `max_nodes`, и имеет вызывающих
- **THEN** ответ с `direction: both` содержит всех вызывающих, если их число не превышает `max_nodes`
- **AND** число occurrence-вершин в ответе не превышает `max_nodes`

#### Scenario: Диагностика по запросу

- **WHEN** агент запрашивает контекст файла, у которого есть диагностика, без `include_diagnostics`
- **THEN** список диагностики в ответе пуст
- **AND** с `include_diagnostics: true` диагностика файла возвращается
