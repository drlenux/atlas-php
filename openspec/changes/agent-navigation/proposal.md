# Proposal

## Why

Обратная связь владельца после замеров на `slotor777` (пункты, которые остались после вывода типов):

- поиск смешивает символ и текст: по `processingGameTransaction` возвращаются `Logger::writeInfo('processingGameTransaction…')`;
- `truncated` равен `true` даже для одной вершины при depth=0;
- нет компактной структуры класса, как `get_symbols_overview` у Serena: контекст `UserBonus` весит 44 КБ, а для класса из 56 методов нужно около 2–3 КБ. Нет и способа получить наследников и реализации, как `find_implementations`;
- агент не знает, насколько свежи данные.

## What Changes

- `atlas_search`: `mode` — `text` (как сейчас) или `symbol` (точное имя объявления, `qualified_name` или `member_name` места вызова, чтения или записи).
- `atlas_context`: `truncated` означает только срез по бюджету; новое поле `depth_limited` сообщает, что за пределом глубины есть соседи.
- Новый инструмент `atlas_outline`: компактная структура класса (члены одной строкой: строка, вид, имя, сигнатура, отметки происхождения), предки, интерфейсы, трейты, наследники и реализации. Для метода — переопределяемый метод и переопределения.
- Свежесть индекса: время последней успешной публикации хранится в БД. Ответы `atlas_search`, `atlas_context` и `atlas_outline` включают `index` (`indexed_at`, `state`, `changes_pending`).

## Capabilities

### Modified Capabilities

- `mcp-context`: режим поиска, семантика усечения, структура класса, свежесть индекса.

## Impact

- `src/{domain,service,repository,postgres,http,progress,project,main}.rs`, `migrations/`, `web/` (подпись контекста).
- MCP: новый инструмент и поля ответа. **BREAKING**: `truncated` больше не ставится только из-за глубины.
- Коммит Git в ответе не возвращается: Git-данные исключены из атласа решением владельца. Свежесть определяется временем публикации и ожидающими изменениями файлов.
