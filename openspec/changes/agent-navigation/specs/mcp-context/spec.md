# MCP context — навигация агента

## ADDED Requirements

### Requirement: MCP-08 Поиск по символу

Поиск через MCP SHALL поддерживать режим `symbol`. В нём совпадением считается только точное (без учёта регистра) имя объявления, его полное имя или имя члена у места вызова, чтения или записи, но не текст выражения.

#### Scenario: Упоминание в строке лога

- **WHEN** метод `processingGameTransaction` вызывается в двух местах, а ещё в одном месте его имя есть только в строке `Logger::writeInfo('processingGameTransaction…')`
- **THEN** поиск `symbol` с kinds `call_site` возвращает два места вызова
- **AND** поиск `text` возвращает все три

### Requirement: MCP-09 Честное усечение контекста

`truncated` SHALL быть `true` только тогда, когда пределы ответа не вместили найденные вершины или рёбра. Достижение глубины SHALL сообщаться отдельно полем `depth_limited`.

#### Scenario: Одна вершина

- **WHEN** агент запрашивает контекст метода с depth 0
- **THEN** `truncated` равно `false`
- **AND** `depth_limited` равно `true`, если у метода есть связи

### Requirement: MCP-10 Компактная структура и иерархия

Система SHALL предоставлять через MCP компактную структуру класса: предков, интерфейсы, трейты, наследников, реализации и члены одной строкой (строка, вид, имя, сигнатура, отметки происхождения). Для метода SHALL предоставляться переопределяемый метод и его переопределения.

#### Scenario: Класс модели

- **WHEN** агент запрашивает структуру класса с 3 методами и свойством из `@property`
- **THEN** ответ содержит 4 строки членов, и строка свойства отмечена `magic` и `annotation`
- **AND** ответ содержит родителя и наследников класса

#### Scenario: Реализации интерфейса

- **WHEN** агент запрашивает структуру интерфейса, который реализуют два класса
- **THEN** ответ перечисляет оба класса в `implementations`

#### Scenario: Переопределения метода

- **WHEN** агент запрашивает структуру метода, который переопределён в наследнике
- **THEN** ответ перечисляет переопределяющий метод в `overridden_by`

### Requirement: MCP-11 Свежесть индекса

Ответы поиска, контекста и структуры SHALL содержать время последней успешной публикации индекса, состояние индексации и признак изменений файлов, ещё не попавших в индекс.

#### Scenario: Правка файла ожидает индексации

- **WHEN** watcher заметил изменение файла, а задержка ещё не истекла
- **THEN** ответ содержит `changes_pending: true` и прежнее `indexed_at`

#### Scenario: Публикация

- **WHEN** публикация индекса завершилась
- **THEN** `indexed_at` равно времени этой публикации и сохраняется после перезапуска сервиса
